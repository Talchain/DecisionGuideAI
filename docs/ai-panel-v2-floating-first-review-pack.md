## 9 · Known limitations

> **Critical** — these must be revisited once the orchestrator / draft-graph backend is reachable from this environment.

1. **Real draft-graph generation was NOT verified through a live backend.** The orchestrator / CEE service is not running in this dev environment. The auto-dock path (`AIInputBar.handleSend` with empty canvas → `sendMessage` with `turnType: 'explicit_generate'` → graph patch from CEE → 0 → N+ node transition) was therefore not exercised end-to-end.

2. **Auto-dock was verified by simulating the 0 → graph transition** via direct `useCanvasStore.setState({ nodes: [...] })` in the browser and via mocked `nodeCount` in the new `FirstUseComposer.spec.tsx`. The state-machine path itself is verified by tests + browser; the *trigger* (orchestrator turn returning a graph patch) is unverified.

3. **This must be manually rechecked once the backend / orchestrator path is available** in a staging environment with a running CEE service. The recommended manual flow:
   - Enable `VITE_FEATURE_AI_PANEL_V2=1` in the staging build.
   - Visit `/canvas` on an empty scenario.
   - Type a real decision brief in the centred first-use composer and hit Send.
   - Confirm the orchestrator turn (`POST /orchestrate/v1/turn`) with `turn_type=explicit_generate` is observed in the network tab.
   - Confirm the resulting graph patch lands and `nodeCount` transitions 0 → N+.
   - Confirm the auto-dock to Analysis tab + "Model drafted. Review readiness." receipt is visible.
   - Re-verify with a slow / failing CEE response to confirm the "Thinking…" status-strip text and the userRepositioned guard.

4. **CogPopover z-index 950** is a pragmatic layer between the staging-pre-existing dock (z 900) and modals (z 1000+). The brief originally specified 400 — this is preserved as an inline comment + header doc in `CogPopover.tsx`.

5. **"Attach evidence" remains "Coming soon"** in the CogPopover. The brief's "functional" requirement requires a backend turn-file contract that does not exist in the orchestrator API; chip-only UI was rejected in earlier review rounds as theatre. The `onAttachEvidence` prop is preserved on `CogPopoverProps` for forward-wiring once the backend lands.

6. **Production-flag exposure risk.** Anyone currently using `feature.aiPanelV2=true` against staging today would experience an immediate hard UX swap from Batch 1 (split-panel) to Batch 2 (floating-first) when this lands. Rollout coordination with whoever tests with the flag on is recommended before merge.
