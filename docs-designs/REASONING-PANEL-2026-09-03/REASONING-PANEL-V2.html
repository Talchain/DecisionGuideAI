A reassessment against the approved prototype, checked at the code rather than from screenshots. My first version of this page claimed nine of eleven rules had regressed. That was wrong. Four of those nine are not regressions at all — two are deliberate, reasoned refusals to render metrics the wire does not license, one is implemented, one is a coverage gap. Corrected count: five genuine regressions, not nine. All five are discipline — type scale, borders, action tiers, colour semantics, question-first. They are real, they are cheap to reverse, and a CI guard can hold them.

The other four were me reading pixels instead of code. Two of them are the important ones, and they point the same way as the naming problem: the prototype specifies three things the data cannot support — short names, per-value provenance, and an inputs proportion. The build discovered all three the expensive way and refused each in writing. So the prototype is not a target we can simply return to.

Where the prototype is undeliverable

Not a criticism of the design — a mockup is allowed to assume its data. But it means “restore the prototype” is the wrong instruction, and I gave it before checking.

Short node names

Assumed. Every name in the prototype was hand-written; real labels are brief prose. This is the contract now routed to the CEE extractor — the display layer cannot be correct in any design without it, including this one.

Per-value provenance

Assumed. The filled/hollow/half dots need to know whose each value is. No carrier supplies it, so the strip renders every mark identically and drops the legend. A fill the data cannot justify is the defect the strip exists to expose.

“4 of 17 inputs are yours”

Assumed. The producer sends a per-factor flag, not a proportion — so the count is a number nothing on the wire licenses. The build says a stated condition instead: “Partly on inputs Olumi estimated.” Weaker-looking, and the only honest reading.

The pattern is one thing, three times: the design asks the render layer for a claim the data does not carry. Naming is the same defect — it is simply the one nobody caught, because prose in a heading still renders, where a fabricated proportion gets challenged. That is why it survived into production and the other two did not.

The one problem the prototype cannot solve

Every node name in the approved prototype was hand-written and short — “Warm Network Activation”, “Time Pressure”. Real labels are brief prose. Feed the real data into the prototype and .oname, .dname and .fnode all break the same way the build does, because they are white-space:nowrap; text-overflow:ellipsis on a string that was never meant to be a name.

PROPOSED — name and claim are different fields

name — ≤42 chars, noun phrase. Headings, axes, chips, sentences.
claim — the full prose. Shown on expand, and nowhere else.

When CEE supplies a name:
Heading → “Product gaps drive churn, not price”
Sentence → If Product gaps → churn shifts, Hire a Sales Team may lead

When it does not — today: the UI truncates at a word boundary and never invents words →
“We've heard from three churned…” with the claim one tap away.

The UI half must never rewrite. Shortening prose into a name is a judgement about meaning; a render layer that guesses it will eventually put a sentence on screen that the model does not support. So the fallback truncates and discloses — visibly worse than a real name, which is the correct incentive, and strictly better than mid-word.

What I changed from the approved prototype, and why

Everything else is the prototype, restored. These are the only deliberate departures.

Method pills are now truthful, or absent The prototype shows Pre-mortem. Today the producer emits codes our technique catalogue has no member for, so a pill would be a fabricated scientific label. Rule: show the method only when the finding maps to a real technique; otherwise the card keeps its question and its one action, and says nothing it cannot support. This is the CEE ask, not a UI fix.
Names truncate; they never rewrite Two driver rows carry raw brief prose, cut at a word boundary with the full claim on hover and expand — plus an explicit prompt to name them. Visibly worse than a real name, deliberately, so the gap creates pressure rather than hiding.
One staleness signal The build fires three at once. One banner, one action, at the panel edge.
The tornado chart is gone It had no zero axis and its own list sat beneath it with the same four items plus exact percentages. The list is the better instrument; the chart was the redundant one.
“Focus now” leads with the target, not the hinge The strongest available move on this model is the missing success target — it unlocks goal-fit, which is the locked lens. The prototype's own logic, applied to this data.
The strip's dots are all identical, and there is no legend Reversing my own first draft. Filled/hollow/half needs per-value provenance nothing supplies. Every mark now means exactly “a node of this kind exists”, and the legend goes with the fill it existed to explain. The N to verify count stays — that one is carried.
No inputs-proportion bar Also reversing my own first draft. A per-factor flag is not a ratio, so the bar was an invented metric. Replaced with the stated condition the build already ships — “Partly on inputs Olumi estimated” — plus a route to which ones, which is answerable.
